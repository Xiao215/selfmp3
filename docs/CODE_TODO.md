Six reviewers read the code by area (server; app shell/player/ports/offline; app features/ui; packages; desktop/doorman/extension; tooling/CI/verify) and every "unused" claim was grep-checked across `apps/` and `packages/`. The items in **Do first** were re-verified by hand.

The repo's own gates all pass at this commit: `typecheck`, `lint`, `check:exports`, and `--noUnusedLocals --noUnusedParameters` on every project (two hits in `apps/app`, listed below). So nothing here is a compile or lint error; it is drift, duplication, leftovers and a handful of real bugs the gates cannot see.

**Labels**

| Label | Meaning |
| --- | --- |
| `HARDCODE` | a value that belongs in one constant, token, config field or env var |
| `DEAD` | code, exports, props, styles, comments or compat shims nothing uses |
| `PROPER` | works, but duplicated, cast around, or built the long way |
| `PERF` | measurable waste on a hot path |
| `ROBUST` | a real bug or a race, usually at an edge |
| `SECURITY` | trust boundary looser than it should be |
| `HYGIENE` | tooling, CI, repo state |

Severity: **H** = fix soon, user-visible or corrupting; **M** = worth a focused commit; **L** = pick up when passing.

Rule reminder from the owner: the project is unreleased, so every "older server / older index / kept so callers need not change" branch is a deletion, not a keep. SQLite schema migrations stay.

## The eight themes

Most of the 76 items are instances of eight root causes. Fixing the cause closes the instances.

### T1 — The range path bridges a promise to a stream by hand, in two different broken ways

**Cause.** `RangeSource.open` (apps/server/src/http/range.ts:25) is declared synchronous while both real sources are promise-shaped, so each of the two implementations invents its own relay stream — and each drops a different half of what `pipeline` gives you (error propagation in one, backpressure and cancellation in the other).

**Covers.** Hand-rolled stream adapters where Readable.from belongs (media.ts:37-49 / s3.ts:195-220); An aborted /api/stream/:id never cancels the bucket fetch it started (media.ts:31-51); S3 range streaming hand-rolls a Readable with a no-op _read (storage/s3.ts:195-220).

**One fix.** Widen the contract to `open(start, end): Promise<NodeJS.ReadableStream>` and `await` it at range.ts:98. Both relay streams (the `PassThrough` at media.ts:38 and the `new Readable({ read() {} })` at s3.ts:196) then delete themselves, `pipeline(upstream, res)` destroys the real upstream when the client seeks or skips, and the unhandled `'error'` event that today reaches `process.on('uncaughtException')` — taking the whole server down for every listener — cannot arise. Three call sites: media.ts:37, storage/local.ts:137, storage/s3.ts:195.

### T2 — Parse, don't cast: the shared contract stops at the wire

**Cause.** zod is the contract for HTTP bodies only; every value read back from SQLite, from device prefs, from a stored JSON blob, from a catch block or from a third-party SDK is re-declared by hand as a `Set`, a `typeof` ladder, an `as` cast or a shim interface — so the schema and its second, weaker restatement can drift with nothing failing.

**Covers.** Union members re-spelled as Sets with double casts in three repositories; The cloud connection and doorman session validated with typeof ladders; The kept device list parsed with hand-written type guards; `(caught as Error).message` in seven catch handlers; The AWS SDK's real types shimmed as `Record<string, unknown>`; Smart-playlist rules are a z.union where the doc says discriminated union; None of the three switches over the rule union is exhaustiveness-checked; A playlist's `kind` and its `rules` are independent fields; The tag-hue primitive written five times; The 30-day date-rule default spelled `?? 30` at four call sites.

**One fix.** One rule, applied in one pass: a value that did not come from a TypeScript expression is parsed, never asserted. Concretely — `Schema.catch(fallback).parse(row.x)` in the three repositories (the house idiom already at repositories/playlists.ts:88-96), `safeParse` for the two stored-secret readers and the device list, `failureText(...)` in the catches, real `@types` imports for the S3 commands, `z.discriminatedUnion('field', …)` for the rule union plus an exported `assertNever` closing all three switches, and `.default(30)`/`HueSchema` so a constant lives once. That also makes true the four places (smartPlaylist.ts:19-21, schemas/smart.ts:8-11, ARCHITECTURE.md:161 and :429) that currently claim the compiler enforces exhaustiveness when it does not.

### T3 — The second copy instead of the import

**Cause.** There is no agreed home for small pure helpers, so the reflex when a second screen or a second repository needs one is to write it again next to the caller; several pairs have already drifted in output, in argument order, or in which of the two is tested.

**Covers.** routes/artists.ts copies the art route's conditional-GET + sendFile block; StatsRepository regex-rewrites its own SQL to add an alias; The admin page re-implements formatBytes and formatRelative (and disagrees); Settings → Cloud re-implements the bucket form's readiness rules; `rgbCss` duplicates `@selfmp3/client`'s `rgba`, and `hexRgb` is a third hex→RGB; Two `clamp` helpers in one folder with the value in different argument positions; clamp/clamp01 defined seven times across three packages; `useSongColor` and `useCoverColor` are the same hook written twice; `PlaybackEngine` declares the wiring fields twice; `refreshSession` is `keepAnswer` written out again; The command palette keeps two parallel orderings of its rows.

**One fix.** Put the pure helpers where the repo already says they go — `clamp`/`clamp01` in `packages/shared` (the server needs them too), `rgba`/`hexToRgb` exported once from `packages/client/src/art/palette.ts`, `http/sendStoredImage.ts` for the two image routes, `addressReady`/`needsRegion` imported into CloudPanel — and delete every second definition rather than aligning it. Where the copy cannot be deleted (admin.js must stay build-free), pin it with a parity test the way tokens.reference.css is pinned. The command-palette case is the same shape one level up: derive the keyboard order and the JSX from one array instead of keeping an `Entry[]` and a `let cursor` in agreement by hand.

### T4 — The platform already has this, and the repo already knows

**Cause.** Node, React and Express idioms were adopted unevenly over time: in almost every case the correct call is already used somewhere in the tree, and the hand-rolled scaffold survives beside it because nothing re-reads the older file.

**Covers.** Seven copies of the AbortController + setTimeout + finally-clearTimeout fetch-timeout scaffold; `files.fetchTo`/`writeText` hand-roll a write-stream promise (reported twice); http/route.ts hand-rolls the async-rejection forwarding Express 5 already does; `forgetCloudLibrary` writes null into seven keys although `DeviceStore.remove()` exists; The native device id falls back to `Math.random` although expo-crypto is already a dependency; `useAppFocused` subscribes with useState+useEffect instead of `useSyncExternalStore`; The extension watcher recomputes `finished()` per batch after computing it for all of them.

**One fix.** One mechanical sweep, each replacement pointing at an in-repo precedent: `AbortSignal.timeout(ms)` for the seven fetch scaffolds (already the shape at desktop/main/updates.ts:103 and doorman/bucket.ts:282), `fsp.writeFile` for the two desktop buffer writes (already the shape at server/storage/local.ts:104), `async (req, res)` handlers on Express 5's own rejection forwarding, `store.remove` (already used by session.ts:148), `newUid(into => into.set(Crypto.getRandomBytes(into.length)))` (already written at CloudPanel.tsx:88), and `useSyncExternalStore` (already used at ~27 sites in apps/app). Note the one test cost: lookup.test.ts drives the timeout with fake timers, which do not reach the timer behind `AbortSignal.timeout`.

### T5 — The gates only see what they can grep, and a pile of dead surface sits behind them

**Cause.** `npm run check` is read as "everything is checked", but five of its parts are narrower than they look — vitest resolves workspace packages through `dist`, `passWithNoTests` hides empty suites, `check:exports` is a regex over `export` declarations so no object or interface member is ever seen, apps/app has no type-aware lint at all, and the two release workflows never call check.yml — so a whole class of defect is invisible and unreachable code accumulates unchallenged.

**Covers.** vitest resolves the workspace packages through their dist; `passWithNoTests: true` hides two empty describe suites naming functions that no longer exist; The desktop and extension release workflows publish builds that have never been typechecked, linted or tested; apps/app hand-copies eleven strictness flags instead of extending tsconfig.base.json; apps/app is the one workspace with no `no-floating-promises`; check:exports never checks a member of an object literal or interface — plus everything it hides: four dead api.ts methods, `previewRules` implemented three times, `StorageDriver.move`, three dead `EngineCapabilities` flags, `EngineState.buffered`, `AudioEngine.toggle()`, `DownloadStorage.configure`'s optionality, `ClientResponse.text()`/`signal`, `DeepLinks.forget()`, `LibraryFilter.query` and its whole unreachable branch, and `prune()` in config.ts.

**One fix.** Close the five holes in one tooling commit — `resolve.alias` (or a `source` export condition) so vitest resolves packages from src, `passWithNoTests: false`, `uses: ./.github/workflows/check.yml` + `needs: check` on desktop.yml and extension.yml, a type-aware block in apps/app/eslint.config.js scoped to `app/**` and `src/**`, and a ~25-line member pass in scripts/unused-exports.mjs driven by a small table of surfaces (api.ts, container.ts, driver.ts, ports/engine.ts) with ALLOWED as the written-down-judgement escape hatch. Then delete, in a second commit, everything that pass surfaces; the project is unreleased, so there is no caller to keep any of it for.

### T6 — The paths nobody exercises: boot, shutdown, and state held across an await

**Cause.** Startup, shutdown and the few genuinely concurrent code paths are the least-run code in the repo and the least testable, so each one hand-manages its own signals, flags and ordering — and each gets one of them wrong in a way no gate and no test can see.

**Covers.** The HTTP server has no 'error' listener, so a busy port is reported as "uncaught exception"; `shutdown()` always exits 0, so launchd never restarts a crashed server; The CLI computes its server address before it reads .env; A graceful shutdown marks every in-flight import `cancelled` instead of requeueing it; `analyse-*` files in the shared staging folder are removed only by a `finally`; IndexedDB delete helpers have no `tx.onabort`, so sign-out can hang forever; `#prepareBucket` guards `format` and `verify` with check-then-act across an await; The extension watcher reads its batch list, goes to the network, then writes back.

**One fix.** Two disciplines, applied to the eight sites. On the process side: one boot/shutdown module that attaches `server.on('error')` with an EADDRINUSE branch, threads an exit code through `shutdown(signal, code)` (forced shutdown always 1), loads `.env` once at the top of `main()` before anything reads `process.env`, and sweeps `analyse-*` leftovers at start the way importQueue.ts:375-378 already sweeps its own. On the concurrency side: never re-test a boolean across an await and never write back a value read before one — hold the in-flight promise (`#adopting` at cloudSync.ts:985-995 is the model), use `store.update`'s single transaction in the extension, distinguish a shutdown abort from a user cancel, and give the two IndexedDB deletes the `tx.onabort` their two siblings in the same file already have.

### T7 — The cloud library is the untested half

**Cause.** `packages/replica` implements a subset of the server's routes and a second evaluator for the same rules, but nothing pins the two halves to each other — so a feature can vanish, a query can poll a permanent 501 forever, and a live playlist can legitimately hold different songs on the two sides, all silently.

**Covers.** The two evaluators break sort ties on different keys, so a limited live playlist differs on a server that adopted a bucket; Forgotten gems is server-only, so the shelf silently disappears from Library and Playlists; `useAccount` polls `GET /api/cloud` forever in a cloud library where it is a permanent 501; Three screens hand-roll `cloudSession.loadSession()` into local state, and the Storage row never updates; Profile asks two different sources for the signed-in account and the cloud branch throws the name away.

**One fix.** Make the shared pure function the only implementation and the replica route a thin caller, as routes.ts:126-136 already does for `similarSongs`: move the gems ranking into `packages/shared` and add the route, break sort ties on `(added_at, uid)` — a key both sides carry — instead of on a local row id and an unstated array-order invariant, and extend the existing server-vs-device cross-check (cloudIngest.test.ts:498) with an adopt-ordered fixture, since today its fixture gives every song the same `added_at` and so cannot catch the divergence. On the client side, one `useCloudSession()` query replaces the four independent reads and gets an `enabled` flag so nothing polls a route its runtime cannot answer.

### T8 — Per-frame values living in per-render containers

**Cause.** React state and Animated node graphs that change at pointer-frame rate are held in the structures meant for values that change per screen — the memoised `PlayerApi` context object, and interpolations rebuilt in the render body — although both files document the correct shape and use it for their other values.

**Covers.** PlayerApi carries the engine's fast-moving sound state, so a volume drag re-renders all usePlayer() consumers; The provider builds a map of every cover on the device to look one song up; Animated interpolations built during render in NowPlayingStage, QueueSheet and Sheet; QueueRail forces the JS driver on the whole rail slide including the iPad layout where the transform could go native.

**One fix.** Apply each file's own documented rule to the members that escaped it: move `volume`/`muted` (and `countingIn`) out of the `PlayerApi` memo into the `createValueStore` entries beside `progress`/`playback`/`stalled` — the stores' doc comment already gives this exact reason for `stalled` — freeze every interpolation in `useState(() => …)`/`useMemo` as StageMove.tsx:49 and QueueRail.tsx:271 already do, split the rail's one `progress` value into a width value (JS driver, necessarily) and a transform value (native), and read one cover with `coverFor` instead of copying the whole map.

## The honest assessment

The honest headline is that this codebase's comments are better than its mechanisms. It is unusually well documented — nearly every hard decision has a paragraph explaining itself — and the recurring defect is a written-down invariant with nothing enforcing it. `smartPlaylist.ts:19-21` and `ARCHITECTURE.md:429` say the compiler will stop compiling when a rule variant is added; it will not, because a trailing `throw` satisfies the return type. `ports/device.ts:55` says `crypto` is present in Hermes; it is not, and `cloudPlatform.ts:134` four files away says the opposite and acts on it. `livePlaylistSongs`'s header says the caller must hand it songs newest-first, and `CloudAdopt` guarantees the id order that makes that assumption reverse. `#prepareBucket` promises "one listing per bucket and nothing thereafter" while guarding two booleans across an await. `http/route.ts` still argues from Express 4. The gap between documented intent and enforced behaviour is where almost every serious finding here lives, and it is structural: the project relies on prose where it could rely on a type, a schema, an index, or a test. The second-order cause is that the check pipeline is narrower than it reads — `check:exports` is a regex over `export` declarations so no object member is ever seen (twelve dead ones behind it, one keeping a whole 49-line service and its route alive), `test:watch` tests stale `dist`, `passWithNoTests` hides suites naming functions that no longer exist, the largest workspace has no type-aware lint, and two release workflows ship signed binaries that were never typechecked. Fix the gates first; they will find the next hundred of these without you.

The concrete weak spots, in order. First, the boundary code where the process meets the outside world: HTTP range streaming (two hand-rolled relay streams, one of which can kill the server on a dropped bucket connection), boot and shutdown (a bind failure looks like a crash, a crash looks like a clean exit, an in-flight import is marked as if a person cancelled it), and anything that has to survive a kill. This code has no test directory, runs rarely, and fails remotely and silently — exactly the profile that justifies spending effort there first. Second, the cloud library is a genuine second-class runtime: the replica implements a subset of routes with a second evaluator, and nothing pins the two halves together, so a shelf disappears with no explanation, a query polls a permanent 501 forever, and a limited live playlist can legitimately hold different songs on the server than on the phone reading the same bucket. The one cross-check that should have caught the last of those passes only because its fixture makes every song the same age. Third, and most pervasive though individually minor: the reflex to write a helper again next to the caller rather than import it. `clamp` seven times in three argument orders, a conditional GET three times, a fetch timeout scaffold eight times, `formatBytes` twice with different output, one hex→RGB three times, one bucket form's readiness rules twice with only one tested. None of these is a bug today; collectively they are the mechanism by which the invariants above stopped being true. A `packages/shared` home for pure helpers and a hard rule that a second implementation of a rule is a defect would prevent more future work than any single fix on this list.
